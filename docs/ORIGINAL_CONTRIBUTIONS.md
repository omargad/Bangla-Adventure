## GitHub's native Contributors display

GitHub's repository Contributors graph counts authored commits that reach the default branch (`main`) when the commit email is linked to the author's GitHub account. Merge commits and empty commits do not count.

On 28 October 2026 the import was rebuilt to reflect Jira ownership. Instead of one commit by the repository owner, the 28 October 2026 package is added by one commit per Jira item. Each commit is authored by the item's Jira assignee through their GitHub no-reply address and committed by `omargad`. These commits reconstruct ownership from the Jira record at import time; the team's day-by-day history is not in the package, and each commit message says so. Files that no individual Jira item covers stay with the repository owner. Commits made after the import keep their real authorship, and the recovered original commits above count for their own authors (Dilsha's for `104985376`).

Disclosure: many files credited to teammates through Jira were already in the August prototype history, committed by `omargad` before the Jira project began on 14 August. The repository owner reports that this was the credited assignees' work, committed to the prototype by `omargad` for the group; each import commit states how many of its files this applies to, and [FILE_OWNERSHIP.md](FILE_OWNERSHIP.md) marks each one.

See GitHub's [project contributor documentation](https://docs.github.com/en/repositories/viewing-activity-and-data-for-your-repository/viewing-a-projects-contributors) for the graph's rules and [missing contribution troubleshooting](https://docs.github.com/en/account-and-profile/how-tos/contribution-settings/troubleshooting-missing-contributions) for account/email and branch requirements. Profile activity and the repository Contributors graph have different scopes.
